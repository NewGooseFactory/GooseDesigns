Sheet 01 · cross-platform Xcode replacement

iOS apps, built from a Linux shell.

xtool replicates Xcode's job with open standards. It builds a SwiftPM package into an iOS app, signs it, and installs it on your device, from Linux, Windows through WSL, or macOS.

Read the install guide View the source
First runfrom the docs
  1. xtool setupOnce: sign in, then point it at Xcode.xip.
  2. xtool newAn iOS-capable Swift package.
  3. xtool devBuild, install and run on the device over USB.

The first build compiles the iOS SDK's Swift modules, so it takes a few minutes. Later runs reuse SwiftPM's global cache.

Revision note · part 3

What changes is where you build, not whose SDK you build against.

You still download Xcode once, in a browser, with your Apple ID. xtool setup extracts the XIP to generate and install an iOS Swift SDK, and swift sdk list then shows darwin.

From there the Mac and the IDE are optional; the README shows xtool driven from VS Code.

Part 5 · sign-in

Two ways to sign in, with the trade-off printed.

0 · API key

The recommended option

Requires a paid Apple Developer Program membership and uses the public App Store Connect API, with a Team Key in the App Manager role.

1 · Password

Works with any Apple ID

Uses private Apple APIs to authenticate, so the docs suggest a throwaway Apple ID if you want to be extra cautious.

From the install guide: your credentials are only sent to Apple and nobody else, and you can build xtool from source to check.
