A Playwright snapshot costs 56 KB. Twenty GitHub issues cost 59 KB. One access log, 45 KB. After 30 minutes, 40% of your context is gone — and when the agent compacts to free space, it forgets which files it was editing and what you last asked for. Context Mode sandboxes the raw data and indexes the session instead.

Four sides of one problem

the fourth is a refusal, not a feature
01

Context saving

Sandbox tools keep raw data out of the window. 315 KB becomes 5.4 KB.

02

Session continuity

Edits, git operations, tasks, errors and decisions are tracked in SQLite and retrieved by search — not dumped back into context. No --continue means previous session data is deleted immediately.

03

Think in code

The model should program the analysis, not compute it. One script replaces ten tool calls.

04

No prose-style enforcement

It never dictates how the model writes its final answer. The project cites evidence that aggressive brevity prompts degrade coding and reasoning benchmarks, and keeps its routing block focused on where data goes, not how the model talks.

Think in code — the project’s own example

// Before: 47 × Read() = 700 KB.  After: 1 × ctx_execute() = 3.6 KB.
ctx_execute("javascript", `
  const files = fs.readdirSync('src').filter(f => f.endsWith('.ts'));
  files.forEach(f => console.log(f + ': ' + fs.readFileSync('src/'+f,'utf8').split('\n').length + ' lines'));
`);

The fourth panel is the one most tools would have left out. A context optimiser has every incentive to also shorten the model’s prose — it would show up as savings. Declining to do that, and publishing why, is a scope boundary rather than a missing feature.
